# Свои — проектная документация

Managed co-renting: сервис, который собирает совместимую группу людей, находит им
большую квартиру и сопровождает совместное проживание. Коливинг без собственного
фондa недвижимости.

## 1. Проблема

- Однушка в Казани ≈ 30 тыс ₽, отдельная комната ≈ 15 тыс ₽.
- Трёшка за 40–50k / 3 человека = **13–17k за изолированную комнату** — цена комнаты,
  но качество жизни выше.
- Молодёжи не хватает двух вещей: найти **совместимых** соседей и иметь **арбитра**,
  когда что-то идёт не так (кто-то съехал, не платит коммуналку и т.д.).

## 2. Решение

Не «Tinder соседей», а оператор совместной аренды:

1. Анкета (бюджет, район, режим, привычки) → 3 минуты.
2. Мэтчинг: жёсткие фильтры + скоринг совместимости.
3. Группа из 3–4 человек с общим бюджетом.
4. Подборка квартир под бюджет группы → заселение.
5. После заселения платформа — арбитр и «отдел кадров»: замена выбывшего жильца.

## 3. Алгоритм мэтчинга (v1)

### Жёсткие фильтры (отсев)
- Бюджеты расходятся больше чем на 5 000 ₽
- Нет пересечения районов (учитывается «Любой»)
- Сроки заселения различаются более чем на ступень
- Несовместимость по полу / предпочтениям соседей
- Курит ↔ не курит; есть питомец ↔ нельзя животных

### Скоринг (0–100)
| Фактор | Вес |
|---|---|
| Режим сна (разница часов) | 15 |
| Чистота (разница баллов) | 15 |
| Гости | 10 |
| Вечеринки | 10 |
| Алкоголь | 10 |
| Общительность | 10 |
| Интересы (Жаккар + бонус) | ~20 |
| Возраст | 10 |

В v2 — обучение на реальных исходах (лайки, заселения, срок проживания, распад групп).

## 4. Воронка MVP

```
трафик (чаты вузов, TG-каналы жилья) → 150 переходов
  → 100 анкет → 50–60 реально ищут
    → 10–15 потенциальных троек
      → 6–8 взаимных мэтчей → 3–5 групп
        → просмотры → 1–3 заселения
```

North Star MVP: **% групп, реально подписавших договор аренды.**
Метрики времени: анкета→мэтч, мэтч→группа, группа→квартира.

Первые источники (Казань): TG «Дом и соседи» (~33k), «Казань без посредников» (~17k),
чатки первокурсников КФУ/КАИ/КНИТУ/КГЭУ/РГУП. Амбассадоры: ~1000 ₽ за реального
заселившегося. Рефералка после заселения.

Supply: ЦИАН «от собственника», трёшки 40–60k, только с изолированными комнатами.
Квартиры ищем **после** формирования группы (inventory on demand) — объявления протухают.

## 5. Монетизация

- С жильца: бесплатно матчиться, 2–5k ₽ за успешное заселение.
- С собственника/риелтора: плата за проверенную группу арендаторов.
- Managed apartments: ежемесячная комиссия за сопровождение (замена жильцов и т.д.).
- B2B: вузы, стажировки, релокация джунов.

## 6. Юридические заметки

- Никакого парсинга телефонов и холодных рассылок без согласия (ст. 18 ФЗ «О рекламе»).
- Отвечаем в контексте объявлений, работаем через админов сообществ, собираем
  добровольные заявки.
- Отношения с собственником — обычный договор найма; платформа — посредник/агент.

## 7. Roadmap

| Этап | Что делаем | Критерий успеха |
|---|---|---|
| 0. MVP (эти 2 недели) | бот + Mini App, ручной подбор квартир | 1 подписанный договор |
| 1. Повторение | 5–10 заселений вручную | конверсия группа→договор >30% |
| 2. Лендинг для собственников | сайт, кабинет собственника | постоянный supply |
| 3. Данные | скоринг v2 на исходах, прогноз оттока | замена жильца < 5 дней |
| 4. Масштаб | второй город, B2B-канал | юнит-экономика ≥ 0 |

## 8. Архитектура

```
Telegram ──polling──▶ Bot (grammY) ──┐
                                     ├──▶ PostgreSQL
Mini App (React) ──HTTPS /api──────▶ Fastify API
                          ▲          │
                     Caddy (TLS) ────┘ static dist/
```

Один Node-процесс обслуживает бота, API и статику Mini App — минимум движущихся
частей на старте. Telegram остаётся каналом уведомлений и роста (share-карточки),
но бизнес-логика живёт в backend, а не в боте.
